一、 什么是 GitHub？和 Git 有什么区别？

很多新手会把 Git 和 GitHub 搞混，先花一分钟把它们分清楚：

💡 一句话理解： Git 是你电脑上的「存档工具」，GitHub 是把存档「同步到云端 + 和别人协作」的平台。你可以只用 Git 不用 GitHub，但用 GitHub 一定会用到 Git。

二、注册 GitHub 账号

第 1 步： 打开 github.com，点击右上角 Sign up。

第 2 步： 输入你的邮箱、设置密码、取一个用户名（Username）。

⚠️ 用户名很重要！ 用户名会出现在你的仓库地址里（github.com/你的用户名/项目名），一旦定下来不太方便改，建议认真取一个。全小写英文 + 连字符是比较稳妥的风格。

第 3 步： 完成邮箱验证（GitHub 会发一封验证邮件，点里面的链接即可）。

第 4 步： 选择免费方案（Free），这就够用了。后面会问你一些问卷（可跳过）。

✅ 完成后你会进入 GitHub 主页，右上角能看到你的头像，说明注册成功了。

五、创建你的第一个仓库

仓库（Repository，简称 repo）就是一个项目的文件夹，GitHub 上所有的代码都放在仓库里。

在 GitHub 网站上创建

第 1 步： 登录 GitHub，点击右上角 + → New repository。

第 2 步： 填写信息：

  • Repository name：仓库名，比如 my-first-project

  • Description：项目描述（可选）

  • Public / Private：公开还是私有，新手选 Public 练手

  • 勾选 “Add a README file”：会自动生成一个说明文件

第 3 步： 点击 Create repository，搞定！🎉

✅ 什么是 README？

README 是项目的「说明书」，用 Markdown 语法写。别人打开你的仓库第一眼看到的就是它。写清楚项目是做什么的、怎么用，是一个好习惯。

六、核心操作：clone、add、commit、push

这是 Git 最核心的四个操作，记住这四个就能完成 80% 的工作。

① clone — 把远程仓库下载到本地

② add — 把修改的文件加入「暂存区」

⚠️ 注意那个点！ git add . 后面有一个英文句号，表示「当前目录下所有改动的文件」。新手经常漏掉这个点。

③ commit — 把暂存区的修改「存档」

✅ commit message 怎么写？

简洁说清楚这次改了什么，比如 “修复登录按钮无法点击的 bug”、”添加用户注册页面”。以后翻历史记录时，这些说明就是你的「存档标签」。

④ push — 把本地存档推送到 GitHub 云端

想加新功能、修 bug，但又怕搞坏现有代码？开一个分支在上面改，改好了再合并回主干。万一改崩了，主干不受影响。这是团队协作的标准做法。

八、Pull Request：协作的第一步

Pull Request（简称 PR） 是 GitHub 上的协作机制。简单说就是：「我改了一些代码，请大家审查一下，没问题就合并进去。」

典型场景

  1. 你 fork（复制）了别人的项目到自己账号下

  2. clone 到本地，开一个分支做修改

  3. push 回你自己的 GitHub 仓库

  4. 在 GitHub 上发起 Pull Request，请求原项目作者审查

  5. 作者审查通过后，点击 Merge 合并

怎么发起 PR

第 1 步： 在你 fork 的仓库页面，切换到你修改过的分支。

第 2 步： 点击 Contribute → Open pull request。

第 3 步： 写清楚标题和说明：「我做了什么修改、为什么」，点击 Create pull request。

✅ 开源贡献： 很多开源项目（Vue、React、Linux 内核等）都欢迎 PR。即使只是修一个文档错别字，也是对开源社区的贡献！

💡 绿色的 Code 按钮是你最常用的入口 — clone 仓库时就从这里复制地址。

⑤ 文件列表

每一行是一个文件或文件夹，从左到右：

  • 点文件夹 → 进入看里面的文件

  • 点文件名 → 查看文件内容

  • 点提交说明 → 看这次提交具体改了什么（diff）

  • 点提交 hash（如 08d4226）→ 跳到这次提交的详情页

  • 最右侧 X Commits → 查看完整的提交历史

⑥ README 预览区

打开仓库默认滚动到的区域，是 README.md 的渲染效果。新手第一件事就是认真读这里，项目是干啥的、怎么装、怎么用，都写在里面。

🎯 打开一个仓库后的正确阅读顺序

  1. 看右上角数据：Stars 多不多 → 判断项目靠不靠谱

  2. 读 README：项目是干啥的、怎么装、怎么用

  3. 看 LICENSE：能不能商用、有没有限制

  4. 看最近提交时间：还在维护吗？太久的可能有问题

  5. 看 Issues：有没有未解决的严重 bug

  6. 点 Code 绿色按钮：复制地址，clone 到本地

📥 第三步：把代码弄到你电脑上

有三种方式，从简单到进阶：

方式 A：Download ZIP（最简单，不需要 Git）

适合：只想看看代码、跑一下，不需要后续更新

  1. 点仓库页面绿色的 Code 按钮

  2. 点 Download ZIP

  3. 解压到你想放的文件夹

⚠️ 缺点：下载的是某个时间点的快照，以后原作者更新了，你拿不到，得重新下载。

方式 B：git clone（推荐！能随时更新）

适合：想在本地用、想跟随后续更新、想学习代码

什么是 clone？

clone = 把整个远程仓库完整复制到你的电脑上，包括所有文件、提交历史、分支信息。

它和「Download ZIP」的区别是：clone 保留了完整的 Git 历史，以后可以 git pull 拉取最新更新。

🎯 新手心法

  • 勤 commit：每完成一小步就提交一次，存档点越密越安全

  • 改之前先 pull：避免和别人的修改冲突

  • 不确定就先 git status：随时了解当前状态
