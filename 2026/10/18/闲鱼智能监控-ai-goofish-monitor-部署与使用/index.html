闲鱼捡漏自动化：ai-goofish-monitor 部署与使用全记录

闲鱼捡漏这件事，难点从来不是”买”，而是”看见”。

好东西挂出来的窗口期可能只有几十分钟，你不可能 24 小时盯着搜索页刷新。所以我一直在找能替我盯着的工具，最近把 GitHub 上的 ai-goofish-monitor 完整装了一遍——Playwright 抓页面、多模态模型看图判断、命中就推手机。这篇是部署过程 + 使用说明，包含我踩的两个坑。

一、它到底做了什么

一句话：你写一句人话需求，它定时去闲鱼搜，把商品图发给视觉模型判断值不值得买，值得就推送给你。

拆开看是四层：

层 干的事
采集 Playwright 驱动 Chromium 打开闲鱼搜索页，翻页、抓详情、抓卖家信息、下图
判断 把图片 + 文案丢给多模态模型，对照你的”标准”输出推荐/不推荐
提醒 ntfy、企业微信、Bark、Telegram、PushPlus、Webhook 任选
管理 Web 界面：任务、账号、AI 标准、日志、结果、设置

任务、结果、价格历史都存在一个 SQLite 文件里（data/app.sqlite3），登录态、日志、图片还是文件形式。比起早期版本扫一堆 jsonl，这版查询和导出让日常使用顺手很多。

二、两条部署路线，先选一条

路线 适合 代价
Docker（官方推荐） 想长期挂着跑、不想碰 Python 环境 要装 Docker，镜像得走国内加速
Windows 本地 Python 想改代码、想看得见浏览器在干嘛 要装 Python + Node，前端要自己构建

我选的是本地部署，因为想确认它到底抓到了什么。下面按这条路线写，Docker 放最后。

环境要求不高：Python 3.10+、Node 18+、一个支持图片输入的模型 API Key。

三、本地部署实录

1. 拉代码

仓库不大，深度克隆只有 7 MB 左右。国内直连卡住的话加个代理：git -c http.proxy=http://127.0.0.1:7897 clone ...。

2. Python 依赖

用 requirements-runtime.txt，不是 requirements.txt——后者多带了 pytest 和 coverage，跑服务用不上。

坑一：injected 镜像源 403。 我一开始习惯性挂了清华源，pip 直接报 403 Client Error 然后 Could not find a version that satisfies the requirement python-dotenv (from versions: none)。这个报错极具误导性，看着像包名写错，实际是源被拦。去掉 -i 用官方源就正常了：

3. 浏览器内核

它靠 Playwright 自带的 Chromium 跑无头模式，跟系统里装的 Chrome 是两回事，这一步别省。

4. 前端构建

157 个包，一分钟左右。坑二在这里：构建产物不是落在 web-ui/dist，Vite 配置里 outDir 指向了 ../dist，也就是仓库根目录的 dist/。你如果在 web-ui 里找 dist 找不到，别以为构建失败了——后端只认根目录那个。

构建完确认 ai-goofish-monitor\dist\index.html 存在，否则打开页面会收到一句”前端构建产物不存在，请先运行 cd web-ui && npm run build”。

5. 配置文件

四、.env 只需要认真填三行

模型必须能看图，否则”判断成色”这件事根本无从谈起。PROXY_URL 可以只给 AI 请求单独挂代理，不影响爬虫。

Web 界面账号在同一文件：

注意 README 里说默认密码是 admin123，而 .env.example 里写的是 admin123。以 .env 为准，这是官方文档没对齐的地方。

几个容易忽略的开关：

  • RUN_HEADLESS=true：无头跑。想盯着浏览器看它在点什么，临时改 false
  • PCURL_TO_MOBILE=true：商品链接转移动端，抓取成功率更高
  • AI_DEBUG_MODE=true：调 Prompt 时打开，能看到模型收到了什么、回了什么
  • TASK_FAILURE_THRESHOLD=3：连续失败 3 次自动暂停任务 24 小时——这是防 cookie 失效后被反复风控的保险丝，别关

通知配一个就够，我用的 ntfy：手机装个 App，订阅一个自建 topic，.env 里填 NTFY_TOPIC_URL，命中就弹。

五、启动与第一次使用

  • Web UI：http://127.0.0.1:8000
  • API 文档：http://127.0.0.1:8000/docs

首次启动会自动建库建表。

导入闲鱼登录态（关键一步）

没有登录态，爬虫抓到的永远是空列表。仓库自带一个 Chrome 扩展，比手工抠 cookie 靠谱：

  1. chrome://extensions → 开”开发者模式” → “加载已解压的扩展程序” → 选仓库里的 chrome-extension 目录
  2. 打开 goofish.com 并登录
  3. 点扩展图标 → Extract Login State → Copy to Clipboard
  4. 回到 Web UI 的「闲鱼账号管理」粘贴保存

它导出的不只是 cookie（含 HttpOnly），还有 UA、时区、屏幕尺寸这些环境指纹，模仿真实会话用。

登录态通常几天到几周失效一次，失效的表现是结果一直是空、日志里刷 cookie 报错，重新导一遍覆盖就行。

建第一个任务

任务管理 → 新建，两种判断模式：

模式 什么时候用 行为
AI 判断 需求能用一句话讲清 填”详细需求”，后台异步生成分析标准（有独立进度弹窗）
关键词判断 价格合适就想看 填关键词规则，直接建任务，不调模型，不花钱

关于参数，有几个经验：

  • 区域筛选会砍掉大部分结果，不确定市场行情时先留空
  • 新发布范围是捡漏的核心，超过 7 天的帖子基本没好价
  • 价格区间两个值别填反（官方示例配置里就填反了，min_price: 8000 配 max_price: 2000，照抄会一个都搜不到）
  • 多账号时把任务绑定到具体账号，同一个账号高频轮询就是给风控递刀

六、跑起来之后看哪里

  • 结果页：从 SQLite 查，可筛选可导出。价格历史也在库里，所以同一件商品降了多少钱是能看出来的
  • 日志页：按任务看每一轮执行细节。排查”为什么今天一条都没推”，答案八成在这里
  • 设置页：改 Prompt、看系统状态、调代理轮换

跑一周之后你会有一个很现实的体会：AI 判断的准确率，八成取决于你写的标准，两成取决于模型。 标准里写”九成新”这种模糊词，模型只能瞎猜；写”边框无划痕、电池健康 90% 以上、含原装充电器”，它就靠谱得多。

七、常见问题速查

页面提示前端产物不存在 → 根目录缺 dist/，回 web-ui 跑 npm run build，重启。

任务一直空结果 → ① 登录态过期 ② 关键词太窄 ③ 区域卡太死 ④ 价格填反 ⑤ 日志里看风控提示，降频率换账号。

AI 判断离谱 → 开 AI_DEBUG_MODE 看输入输出，再改 prompts/ 下的标准文件，别急着换模型。

想 24 小时挂着 → 本地黑窗口不靠谱，换 Docker + restart: unless-stopped。

八、几句必要的提醒

  • 遵守闲鱼用户协议和 robots.txt，轮询间隔别低于 15 分钟，多账号分摊压力。这不是道德洁癖，高频请求的直接后果是你自己的号被封。
  • state/ 里的登录态等于账号钥匙，.env 里有 API Key，两个都别进公开仓库（.gitignore 已经排除了）。
  • 默认密码一定要改，也别把 8000 端口直接暴露到公网——这玩意儿能改你的任务、能读你的通知配置。
  • 项目是 MIT 许可、按”现状”提供，账号风险和后果自己承担。它是个效率工具，不是外挂。

装完之后我的实际感受：这类工具真正省的不是钱，是注意力的持续占用。以前刷闲鱼是每隔两小时想起来一次，现在是有值得看的才响一下。工具负责盯，人只负责决策——这才是我想要的自动化。
