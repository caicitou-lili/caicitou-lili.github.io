## 一、DeepSeek Harness 是什么？

**Harness** 这个词翻译过来就是「驾驭」。如果把 AI 模型比作一匹马，那 Harness 就是你驾驭 AI 模型这匹马所需要的一切工程。

所谓 Harness 工程，就是研究怎么让 AI 模型这匹马跑得更快、更稳，顺利完成任务。你给 AI 写的项目规则文件、配置的各种工具、安排的任务拆分和执行顺序、设计的测试检查流程，这些统统都算 Harness。

有一个很精妙的公式：

> **Agent = Model + Harness**

模型负责思考和生成，Harness 负责把这些能力接入文件系统、终端、网页、工具链，让 AI 真正能在现实环境里干活。

之前 DeepSeek 只开源了模型这一半，Harness 一直没动静，这次终于补齐了。你可以把 DeepSeek Harness 理解成一个可以高度定制的 AI 编程工具，对标 Claude Code 和 Codex。但它的野心比这些工具更大——不只是一个编程 Agent，而是一套可配置、可重组的 Agent 运行环境。官方口号是「**一切皆插件**」。

## 二、安装

安装 DeepSeek Harness 真的非常简单。进入 [DeepSeek Harness 官网](https://harness.deepseek.com/)，你会看到一行安装命令。

在执行之前，首先要确保你的电脑已经安装了 Node.js 环境，没有的话去 [Node 官网](https://nodejs.org/) 下载安装包，傻瓜式安装就行。

有了环境后，复制这行命令，打开终端执行：

```bash
npx @deepseek-ai/dsh web
```

稍等一会儿，终端会输出一个网址，打开它就能进入 DeepSeek Harness 的 Web 界面。

第一次使用时，需要填入 DeepSeek 的 API Key。到 [DeepSeek 开放平台](https://platform.deepseek.com/) 创建一个 API Key（注意不要泄露），把得到的 Key 复制粘贴过来就行。

到这里，DeepSeek Harness 就安装成功了，是不是很简单？

## 三、Harness 实战

界面打开之后，别急着让它干活。第一次用，建议先把下面三件事搞清楚。

### 1. 选一个"工作现场"

第一步是**选择一个项目文件夹**。Harness 会把这个目录当成它的工作现场——之后读文件、改代码、跑命令，全部围绕这个目录展开。

这一点很关键：**目录选错，它能帮你的范围也就错了**。所以第一次实测，我建议不要直接对着你最重要的项目开刀，先建一个空目录玩两把，熟悉了再上真项目。

### 2. 调三个开关

进入对话后，界面上有几个需要你决定的东西：

- **模型与推理等级**：可以选 DeepSeek V4 Pro 等模型，并调节推理等级。等级越高，它越舍得"想"，但响应更慢、消耗也更大。日常改代码用中等档就够，遇到复杂重构再拉满。
- **权限范围**：Harness 默认会在每一次写文件、执行终端命令前向你确认。刚开始强烈建议保持确认模式，等你摸清它的脾气再考虑放开。
- **工作模式**：最实用的是「**标准模式**」。它已经预置了一整套 AI 编程工具该有的基础能力（读写文件、执行命令、检索资料、把长任务拆成待办清单等），开箱就能干活。想更轻量或更激进，再去看其他模式。

### 3. "一切皆插件"到底指什么

官方那句"一切皆插件"不是宣传口号。模型接入、工具能力、执行环境、上下文管理、甚至对外接口，都是可以被替换、被组合的插件。

对普通用户来说，实际意义是：**你不需要用它的全部，按需开关就行**。用得越少，行为越可控，出问题的面也越小。

### 4. 实测案例：让它做一个 Excel 周报生成器

光看界面没感觉，我直接上了一个真实需求：**把每周的几份数据汇总成一份 Excel 周报**。

我给它的原话大概是这样：

> 在当前目录建一个脚本，读取 `data/` 里本周的表格文件，汇总成一份 Excel 周报，包含本周汇总、和上周的环比，输出到 `output/` 目录。

接下来发生的事，是这次实测里最有意思的部分：

1. 它**没有立刻开写**，而是先把任务拆成了一份待办清单（todo），然后一条条执行、一条条勾掉——你能实时看到它"走到哪一步了"。
2. 它自己去**翻了目录里的真实文件**，发现列名和我描述的不完全一样，于是回来问我确认字段含义，而不是硬按自己的假设写下去。
3. 建目录、写脚本、装依赖、跑一遍验证输出，整个过程里每一次写文件和执行命令都弹了确认，我点了几次"同意"。
4. 第一版跑出来的表头不对，我只说了一句"周次那一列要按 ISO 周算"，它就定位到对应函数改掉了，并且重跑验证。

整个过程不到二十分钟，我拿到了一份能直接用的周报脚本。

**这次实测给我最大的感受是**：它和"聊天窗口里让 AI 写代码"完全不是一回事。区别不在于模型多聪明，而在于它**能看到真实文件、能执行、能验证、能被打断和纠偏**——这才是 Harness 的价值。

### 5. 给它写好"项目规则"

这是我用完最想安利的一条经验。

在项目根目录放一个规则文件（比如 `AGENTS.md`），把项目约定写清楚：

- 用什么语言、什么框架，依赖怎么装
- 目录结构长什么样，新文件该放哪
- 改完代码要跑什么检查、什么测试
- 哪些目录是禁区，不许动

Harness 每次启动都会读这份规则。**规则写得越清楚，它越少自作主张**；规则含糊，你就得反复纠正。这一步偷懒，后面全是加班。

### 6. 几个必须提醒的坑

- **权限别一上来就给满**。它能读写文件、能执行命令，就意味着提示词写得含糊时，它可能做出你并不想看到的操作。
- **推理等级拉满很烧 token**。等级越高越慢越贵，注意账户余额，别在简单任务上开满档。
- **它还在开发者预览阶段**。接口会以破坏兼容的方式快速演进，今天写的插件明天可能需要改，别急着上生产环境。
- **别指望它替代你判断**。它能帮你把活干完，但需求是否合理、结果是否正确，责任还是在你身上。

## 四、小结：值得现在上手吗

一句话总结：**DeepSeek Harness 补上了 DeepSeek 生态里一直缺的那一半**。

模型能力大家都已经见识过了，真正拉开差距的是"怎么用好"。Harness 把文件系统、终端、工具链、任务编排这一整套东西开放出来，让"用一个模型"变成"组装一个能干活的 Agent"。

我的建议是：

- **想尝鲜**：`npx @deepseek-ai/dsh web` 一条命令就能跑起来，成本极低，值得试。
- **想认真用**：先花半小时把项目规则文件写好，收益最大的一步就是这个。
- **想上生产**：再等等。开发者预览阶段，接口变化快，现在铺开容易返工。

工具会一直有新的，但"怎么把事情拆清楚、怎么给 AI 划好边界"这套能力，换哪个工具都用得上。

就这样，去玩吧 🎉
