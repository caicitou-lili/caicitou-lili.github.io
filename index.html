MoneyPrinterTurbo 实测：给它一个主题，自动生成一条短视频

一句话说明它是干什么的：

你给它一个主题或关键词，它自动写脚本 → 找素材 → 配音 → 加字幕和背景音乐 → 合成一条竖屏/横屏短视频。

这就是 MoneyPrinterTurbo。名字起得很直白（”印钞机涡轮增压”），是 GitHub 上很火的一个开源短视频生成项目，支持 WebUI、API、命令行三种用法。我把它完整装了一遍，下面是从零到出片的全过程和踩过的坑。

一、先说结论：适合谁，不适合谁

适合：

  • 想批量做口播类/图文类短视频，但不想一条条剪的人
  • 想给自己的内容配一条”能发出去”的视频，又不打算学剪辑软件
  • 想折腾一下 AIGC 工作流，看看”自动化”到底能做到哪一步

不适合：

  • 想要电影级、原创度极高的成片。它的素材来自公共图库，配的是 AI 合成音，本质是”高质量模板化拼装”
  • 想完全免费、零配置。写脚本这一步必须接一个大模型 API，这一步要花钱（很便宜，但不是零）

唯一必填的是一个 LLM 的 API Key，用来生成视频脚本。语音合成默认走 Edge TTS，免费、不用 Key，开箱即用。

二、动手前，先准备三件事

项目 是否必填 说明
LLM API Key 必填 写视频脚本用。支持 DeepSeek、Kimi、OpenAI、通义千问、Gemini 等，推荐 DeepSeek 或 Kimi，便宜
语音合成 免配置 默认 Edge TTS，免费无需 Key。想更好听可以换 Azure / MiniMax / ElevenLabs（要各自的 Key）
视频素材 建议配 默认从 Pexels 拉免费素材，需去官网注册一个免费 API Key；不想注册就切「本地素材」

环境上只有一个硬要求：Python 3.11 或更高版本（项目里写死了 requires-python >= 3.11）。

四、第一次打开，只要填三项

首次启动时，程序会从 config.example.toml 自动生成一份 config.toml。绝大多数设置都能在 WebUI 的「基础设置」面板里填，会自动保存，不用手改文件。

要填的其实就三项：

  1. LLM 供应商 + API Key —— 选一个（默认是 Kimi/Moonshot），把 Key 填上。这一步不填，后面什么都生成不了。
  2. 语音 —— 保持默认的 Edge TTS 就好，免费。
  3. 素材来源 —— 填 Pexels 的 API Key（去 pexels.com/api 免费注册），或者把 video_source 改成 local，用自己放进去的素材。

顺手值得调的还有两个：

  • edge_tts_timeout：Edge TTS 单次请求超时。网络慢的话调大一点。
  • subtitle_provider：字幕默认 edge（免费、快）；想更准可以切 whisper，但首次要下载模型，CPU 上会慢。

五、生成一条视频是什么体验

回到主页，在主题框里输入你想做的内容，比如：

AI 如何改变普通人的日常生活

点生成，接下来它会自己走完这一串：

  1. 调大模型写一段视频文案
  2. 把文案拆成关键搜索词，去素材库拉对应的视频片段
  3. 用 Edge TTS 合成配音
  4. 生成字幕、配上背景音乐
  5. 渲染合成，输出成片

几分钟后你会在任务目录里拿到结果（config.toml 里可以设成生成完自动打开目录）。成片不满意，可以在界面上试听语音、换字体、换背景音乐，再重新导出。

六、到底花多少钱

环节 成本
语音合成（Edge TTS） 免费
视频素材（Pexels） 免费（注册拿 Key）
大模型写脚本 按平台计费，DeepSeek / Kimi 都很便宜，一次生成通常几分钱级别

**所以它不是一个”收费软件”，而是一个”自备 API 的自建工具”**。唯一的持续成本就是调用大模型的那点钱。

七、踩坑与建议

  • 项目路径不要带中文和空格。这类 Python + 多媒体工具链对路径编码很敏感，直接放个 D:\MoneyPrinterTurbo 最稳。
  • 别在 C 盘临时目录里跑。渲染中间产物会占不少空间。
  • 首次跑建议用「本地素材」试。先排除素材源的问题，确认整条链路通了，再去接 Pexels。
  • 网络问题要有心理准备。素材下载、依赖安装、模型调用都可能受网络影响，把代理配好能省很多事（config.toml 里有 [proxy] 段可以直接填）。
  • 音频编码相关的坑：Python 3.13 环境下项目会额外装 audioop-lts，如果看到 audioop 相关报错，检查这个包有没有装上。
  • 别指望零修改出爆款。它的定位是”把你从剪辑里解放出来”，选题、脚本打磨、成片审核，还是得你来。

小结

MoneyPrinterTurbo 是目前这类工具里完成度相当高的一个：WebUI 够用、配置项清晰、语音和素材都有免费方案，一条命令就能跑起来。

我的建议是先用一键包或 Docker 花十分钟跑通一遍，确认工作流符合你的预期，再决定要不要本地部署长期用。先跑通，再优化——这类工具最容易死在”装环境”这一步，而不是”用起来”。

装好之后你会发现，真正花时间的不是生成，而是想清楚要做什么内容。工具把执行的成本压到很低了，剩下的就看你自己的选题了。

DeepSeek Harness 首发实测 + 入门教程

昨天注定是载入史册的魔幻一天，DeepSeek 同时放了两个大招！先是 DeepSeek V4 Pro 正式版上线，紧接着万众瞩目的 DeepSeek Harness 开源。炸裂！炸裂！炸裂！

DeepSeek Harness 开源的 GitHub 仓库上线不到 1 天，就冲到了 8 万多 Star，AI 圈的顶流果然名不虚传。这下搞不好 Codex、Claude Code、Cursor 都要”凉了”……

这篇文章我会从安装开始，手把手带你体验 DeepSeek Harness 的核心玩法。小白可懂，建议收藏 ⭐️

建议观看视频版：B站视频

一、DeepSeek Harness 是什么？

Harness 这个词翻译过来就是「驾驭」。如果把 AI 模型比作一匹马，那 Harness 就是你驾驭 AI 模型这匹马所需要的一切工程。

所谓 Harness 工程，就是研究怎么让 AI 模型这匹马跑得更快、更稳，顺利完成任务。你给 AI 写的项目规则文件、配置的各种工具、安排的任务拆分和执行顺序、设计的测试检查流程，这些统统都算 Harness。

有一个很精妙的公式：

Agent = Model + Harness

模型负责思考和生成，Harness 负责把这些能力接入文件系统、终端、网页、工具链，让 AI 真正能在现实环境里干活。

之前 DeepSeek 只开源了模型这一半，Harness 一直没动静，这次终于补齐了。你可以把 DeepSeek Harness 理解成一个可以高度定制的 AI 编程工具，对标 Claude Code 和 Codex。但它的野心比这些工具更大——不只是一个编程 Agent，而是一套可配置、可重组的 Agent 运行环境。官方口号是「一切皆插件」。

三、Harness 实战

界面打开之后，别急着让它干活。第一次用，建议先把下面三件事搞清楚。

1. 选一个”工作现场”

第一步是选择一个项目文件夹。Harness 会把这个目录当成它的工作现场——之后读文件、改代码、跑命令，全部围绕这个目录展开。

这一点很关键：目录选错，它能帮你的范围也就错了。所以第一次实测，我建议不要直接对着你最重要的项目开刀，先建一个空目录玩两把，熟悉了再上真项目。

2. 调三个开关

进入对话后，界面上有几个需要你决定的东西：

  • 模型与推理等级：可以选 DeepSeek V4 Pro 等模型，并调节推理等级。等级越高，它越舍得”想”，但响应更慢、消耗也更大。日常改代码用中等档就够，遇到复杂重构再拉满。
  • 权限范围：Harness 默认会在每一次写文件、执行终端命令前向你确认。刚开始强烈建议保持确认模式，等你摸清它的脾气再考虑放开。
  • 工作模式：最实用的是「标准模式」。它已经预置了一整套 AI 编程工具该有的基础能力（读写文件、执行命令、检索资料、把长任务拆成待办清单等），开箱就能干活。想更轻量或更激进，再去看其他模式。

3. “一切皆插件”到底指什么

官方那句”一切皆插件”不是宣传口号。模型接入、工具能力、执行环境、上下文管理、甚至对外接口，都是可以被替换、被组合的插件。

对普通用户来说，实际意义是：你不需要用它的全部，按需开关就行。用得越少，行为越可控，出问题的面也越小。

4. 实测案例：让它做一个 Excel 周报生成器

光看界面没感觉，我直接上了一个真实需求：把每周的几份数据汇总成一份 Excel 周报。

我给它的原话大概是这样：

在当前目录建一个脚本，读取 data/ 里本周的表格文件，汇总成一份 Excel 周报，包含本周汇总、和上周的环比，输出到 output/ 目录。

接下来发生的事，是这次实测里最有意思的部分：

  1. 它没有立刻开写，而是先把任务拆成了一份待办清单（todo），然后一条条执行、一条条勾掉——你能实时看到它”走到哪一步了”。
  2. 它自己去翻了目录里的真实文件，发现列名和我描述的不完全一样，于是回来问我确认字段含义，而不是硬按自己的假设写下去。
  3. 建目录、写脚本、装依赖、跑一遍验证输出，整个过程里每一次写文件和执行命令都弹了确认，我点了几次”同意”。
  4. 第一版跑出来的表头不对，我只说了一句”周次那一列要按 ISO 周算”，它就定位到对应函数改掉了，并且重跑验证。

整个过程不到二十分钟，我拿到了一份能直接用的周报脚本。

这次实测给我最大的感受是：它和”聊天窗口里让 AI 写代码”完全不是一回事。区别不在于模型多聪明，而在于它能看到真实文件、能执行、能验证、能被打断和纠偏——这才是 Harness 的价值。

5. 给它写好”项目规则”

这是我用完最想安利的一条经验。

在项目根目录放一个规则文件（比如 AGENTS.md），把项目约定写清楚：

  • 用什么语言、什么框架，依赖怎么装
  • 目录结构长什么样，新文件该放哪
  • 改完代码要跑什么检查、什么测试
  • 哪些目录是禁区，不许动

Harness 每次启动都会读这份规则。规则写得越清楚，它越少自作主张；规则含糊，你就得反复纠正。这一步偷懒，后面全是加班。

6. 几个必须提醒的坑

  • 权限别一上来就给满。它能读写文件、能执行命令，就意味着提示词写得含糊时，它可能做出你并不想看到的操作。
  • 推理等级拉满很烧 token。等级越高越慢越贵，注意账户余额，别在简单任务上开满档。
  • 它还在开发者预览阶段。接口会以破坏兼容的方式快速演进，今天写的插件明天可能需要改，别急着上生产环境。
  • 别指望它替代你判断。它能帮你把活干完，但需求是否合理、结果是否正确，责任还是在你身上。

四、小结：值得现在上手吗

一句话总结：DeepSeek Harness 补上了 DeepSeek 生态里一直缺的那一半。

模型能力大家都已经见识过了，真正拉开差距的是”怎么用好”。Harness 把文件系统、终端、工具链、任务编排这一整套东西开放出来，让”用一个模型”变成”组装一个能干活的 Agent”。

我的建议是：

  • 想尝鲜：npx @deepseek-ai/dsh web 一条命令就能跑起来，成本极低，值得试。
  • 想认真用：先花半小时把项目规则文件写好，收益最大的一步就是这个。
  • 想上生产：再等等。开发者预览阶段，接口变化快，现在铺开容易返工。

工具会一直有新的，但”怎么把事情拆清楚、怎么给 AI 划好边界”这套能力，换哪个工具都用得上。

就这样，去玩吧 🎉

做内容最该装的5个AI Skills——从选题到复盘全流程

做内容最痛苦的不是写不出来，而是每天都要重新找选题、重写提示词、反复改文案、手动分发，还不知道有没有用。
