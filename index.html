一、 什么是 GitHub？和 Git 有什么区别？

很多新手会把 Git 和 GitHub 搞混，先花一分钟把它们分清楚：

💡 一句话理解： Git 是你电脑上的「存档工具」，GitHub 是把存档「同步到云端 + 和别人协作」的平台。你可以只用 Git 不用 GitHub，但用 GitHub 一定会用到 Git。

二、注册 GitHub 账号

第 1 步： 打开 github.com，点击右上角 Sign up。

第 2 步： 输入你的邮箱、设置密码、取一个用户名（Username）。

⚠️ 用户名很重要！ 用户名会出现在你的仓库地址里（github.com/你的用户名/项目名），一旦定下来不太方便改，建议认真取一个。全小写英文 + 连字符是比较稳妥的风格。

第 3 步： 完成邮箱验证（GitHub 会发一封验证邮件，点里面的链接即可）。

第 4 步： 选择免费方案（Free），这就够用了。后面会问你一些问卷（可跳过）。

✅ 完成后你会进入 GitHub 主页，右上角能看到你的头像，说明注册成功了。

五、创建你的第一个仓库

仓库（Repository，简称 repo）就是一个项目的文件夹，GitHub 上所有的代码都放在仓库里。

在 GitHub 网站上创建

第 1 步： 登录 GitHub，点击右上角 + → New repository。

第 2 步： 填写信息：

  • Repository name：仓库名，比如 my-first-project

  • Description：项目描述（可选）

  • Public / Private：公开还是私有，新手选 Public 练手

  • 勾选 “Add a README file”：会自动生成一个说明文件

第 3 步： 点击 Create repository，搞定！🎉

✅ 什么是 README？

README 是项目的「说明书」，用 Markdown 语法写。别人打开你的仓库第一眼看到的就是它。写清楚项目是做什么的、怎么用，是一个好习惯。

六、核心操作：clone、add、commit、push

这是 Git 最核心的四个操作，记住这四个就能完成 80% 的工作。

① clone — 把远程仓库下载到本地

② add — 把修改的文件加入「暂存区」

⚠️ 注意那个点！ git add . 后面有一个英文句号，表示「当前目录下所有改动的文件」。新手经常漏掉这个点。

③ commit — 把暂存区的修改「存档」

✅ commit message 怎么写？

简洁说清楚这次改了什么，比如 “修复登录按钮无法点击的 bug”、”添加用户注册页面”。以后翻历史记录时，这些说明就是你的「存档标签」。

④ push — 把本地存档推送到 GitHub 云端

想加新功能、修 bug，但又怕搞坏现有代码？开一个分支在上面改，改好了再合并回主干。万一改崩了，主干不受影响。这是团队协作的标准做法。

八、Pull Request：协作的第一步

Pull Request（简称 PR） 是 GitHub 上的协作机制。简单说就是：「我改了一些代码，请大家审查一下，没问题就合并进去。」

典型场景

  1. 你 fork（复制）了别人的项目到自己账号下

  2. clone 到本地，开一个分支做修改

  3. push 回你自己的 GitHub 仓库

  4. 在 GitHub 上发起 Pull Request，请求原项目作者审查

  5. 作者审查通过后，点击 Merge 合并

怎么发起 PR

第 1 步： 在你 fork 的仓库页面，切换到你修改过的分支。

第 2 步： 点击 Contribute → Open pull request。

第 3 步： 写清楚标题和说明：「我做了什么修改、为什么」，点击 Create pull request。

✅ 开源贡献： 很多开源项目（Vue、React、Linux 内核等）都欢迎 PR。即使只是修一个文档错别字，也是对开源社区的贡献！

💡 绿色的 Code 按钮是你最常用的入口 — clone 仓库时就从这里复制地址。

⑤ 文件列表

每一行是一个文件或文件夹，从左到右：

  • 点文件夹 → 进入看里面的文件

  • 点文件名 → 查看文件内容

  • 最右侧 X Commits → 查看完整的提交历史

2. 编写剧本

我的输入其实很口语化，就是把脑子里的画面说给它听：家族企业只有一个女继承人，她被董事会的人搞了，最无助的时候，保镖出来救场。要有冲突、有反转，角色别太多，一分钟到80秒左右，背景放在中国。

GPTS会根据这些想法输出完整剧本，我看完再改。比如女主不能一直等人救，她自己得有反驳；监控也不能只拍赵董事进了财务室，最好能看到他拿印章、盖章、刷卡，证据才接得上。

3. 准备资产

这一步我觉得很关键。我们拍的是现代家族企业，人物穿着就偏职业风，主要场景用现代会议室。总不能故事讲董事会，人物和房间却各有各的风格。

女主是继承人，我希望她看起来是被富养长大的女孩：自然、有气质，有一点贵气，不需要浓妆或者把所有昂贵的东西都穿在身上。

最后用了白短外套、深色长裤和暗红胸针，放在一群深色西装里也比较显眼。

男主虽然是保镖，但他也是男主，所以一定得帅，给人安全感。

我们最早那版还戴眼镜，看着像大学生或者程序员，我当时就说，这哪里像能打得过反派打手？后来选中一张脸，继续换西装、调身材比例，才有现在这个样子。

反派打手的造型就可以粗粝一点、凶狠一点，别所有人都长得像精修男模。

女主父亲，我想要的是四五十岁、已经成功的商业掌权者，有一点教父式的威严；

其他高管也要有年龄感，可以稍微发福。大家站在一起，观众才分得清谁是什么人。

人物参考图用的就是上面这种白底三栏：正面脸部大特写、遮住脸的正面全身、背面全身。

这个做法是我最近看Higgsfield公开创作流程学来的。正面全身里的脸涂掉，只用大特写提供脸部信息；全身图负责身材和衣服，背面负责背后的结构。这样可以减少两张脸不完全一样、模型不知道该参考哪一张的干扰。参考资产准备教程

保持已选定的人物身份和脸型，做一张纯白背景角色参考板：左边是清晰的正面脸部大特写，中间是头顶到鞋底完整的正面全身，仅遮住脸部，右边是背面全身。人物比例修长自然，服装、鞋子前后一致，不要加文字。

但要跟视频模型说清楚，黑块只是参考图的处理方式，成片人物的脸必须完整。我们前面真的生成过遮脸画面，所以这个说明不能省。一致性也要继续看原片，不能做完三视图就完全不管了。

场景同样先固定下来。我们这间会议室的门、窗、长桌和主位，后面换镜头还得是同一间房。

再让人物进到场景里试一张构图。人的比例、窗光的方向、手和桌子的接触都要看。前面女主像贴上去的，就是不能只顾脸好看，还得让她真的站在这个空间里。

4. 编排视频提示词

到了视频提示词这一步，我用了一份具有视听语言专业知识的提示词模板。它会结合短剧节奏，把景别、运镜、人物表演和段落衔接编排进去。

我觉得资产图和提示词，是生成视频特别关键的两个东西。前面把它们弄好，后面才能少一点盲目抽卡。

把剧本、资产图和模板一起发给Codex，就可以接着说：

按我提供的提示词模板，把这集拆成可以连续生成的几批素材。
每批写清参考图用途、开场站位、人物表演、对白、景别和运镜，结尾停在哪里也要说明。台词用已经确认的版本。打戏单独调用我们的打斗Skill细化。

一批素材里面可以有几个镜头，不用一句台词生成一条。也别为了凑满时长，让人物站着发呆。

尤其是表演，你得写。

我这次用可灵的感觉是，不把反应说清楚，它真的会很尴尬。一个画面里好几张脸，大家都不怎么动，也没表情，看久了甚至有点毛骨悚然。

所以女主听到父亲让她停职，不要只写她很伤心。

可以写她撑桌的手指收紧，短吸一口气，抬眼看父亲；父亲听完，避开她的目光。旁边的赵董事看向门口，等着保安过来。每个人在这个时候做什么，都得有原因。

比如我们停职这一段，提示词就是这么组织的：

父亲近景，放下笔，看向女儿：交印章。停职调查。镜头轻推。
切女主侧面肩胸近景，画面下缘看得到她撑桌的手。她手指收紧，压着委屈说：爸，你连我一句话都不肯信？
切父亲近景，他看她一眼，又低下眼：我只看证据。
切赵董事中近景，他马上向门口抬手：带走！

景别也要换。先让观众知道大家在哪，再切近一点看表情或动作，别整段都用一个全景。一直远远看着，既枯燥，也容易把那些不自然的小动作全露出来。

打戏我们另外用了专门的打斗Skill。没装过的，可以让Codex安装GitHub上的 ZzzAloong/fight-scene-director。

我自己对比下来，确实更喜欢用了Skill的那一版。下面这两条就是早期实测，同一组5张参考图，同一个可灵4.0，都是10秒、1080P。一条用原提示词，一条用Skill细化提示词。

▶ 约 20 秒视频演示，原帖内可播放

这一组我更偏向后者，但两条仍有不自然的地方，后面也继续返修了。

打斗肯定要有快有慢。

靠近、对峙可以稍缓，出招和反击要利落，失衡落地又得给观众看清楚。Skill帮我们把来招、应对、接触、结果写出来，比只写激烈打斗要具体得多。

运镜也要跟动作匹配。

人都打到画面边上了，镜头还稳稳待在原地，就容易像旁边摆了一台监控。

当然不是越晃越好，走位时跟过去，接触时看清楚，冲突结束再稳下来。我们后面还加过6秒动作视频参考，主要借它的速度和摄影节奏。

5. 生成与返修

参考图和提示词准备好，就让Codex提交。这次用的是可灵4.0，16:9、1080P，有音画同步，保留对白和现场音效。背景音乐、字幕和屏幕文字留到后期统一做。

按这批提示词和参考素材生成视频，先核对图片顺序和每张图的用途。角色的脸只参考对应大特写，遮脸全身只参考服装和身材。用可灵4.0、1080P、16:9，保留对白和现场音效，不生成字幕和背景音乐。保存任务编号，完成后下载原片给我看。

上传、查询和下载都可以交给它。我们中间遇到上传请求过多，就改成逐张上传；电脑不小心关机了，回来按已有任务编号接着查，不用从头再来。

按我自己的使用经验，资产和提示词准备充分后，不少镜头生成1—3次就能接近想要的效果。但难的打戏、前后衔接，还是得多花心思。这次也没有一次全过。

比如我后来发现29秒保镖动手很突然，就直接跟它说：我没看懂他怎么过来的，前后接不上。让它补上保安靠近女主、男主进门制止、对方继续攻击、男主反击这一段。

补拍时，我们用了这张状态还正确的入场画面，再配人物、会议室和动作参考。下面先看旧版，再看调整后的同一时间段。

▶ 约 16 秒视频演示，原帖内可播放

文字也是一个问题。我这次在可灵里生成的证据界面，有些字还是不像正常中文，直接放在片子里很出戏，这一块我觉得还需要加强。

如果某个画面特别依赖清晰的文字和构图，我会更倾向先用GPT Image 2.5把关键帧做清楚、检查好，再拿关键帧生成视频。

这是一种可以尝试的办法，字在运动里仍然可能变形；需要观众准确读到的信息，后期加字更好控制。

6. 剪辑与复盘

原片出来以后，我们就在同一段对话里继续拼接和修改。

我没有打开剪映去拖时间线，而是直接告诉Codex：哪段删掉，哪段加快，哪里补声音。

比如有一段打完之后，人物站在那里停了一下，45秒附近看起来像卡住了。与其硬留着，最后就把上一版44.25—46.25秒那两秒剪掉。灰衣壮汉进场稍微加快到约1.3倍，交手处加一点推近和跟随裁切，节奏才收紧。

▶ 约 0 秒视频演示，原帖内可播放

监控画面也做了后期包装。

我们加上中文机位名、录像状态和时间码，让它看起来更像监控。那些奇怪的证据文字则拿掉，换成赵董事取章、盖章、刷卡的画面，保留保镖指认他的对白，观众更容易看懂。

▶ 约 0 秒视频演示，原帖内可播放

音乐不用一直铺满。

我让它在停职、解围和结尾点缀几下，最后等女主问完父亲，再落一个反转重音，接父亲的反应。话还没说完就急着放音乐，情绪反而容易跑掉。

这些修改，直接这么说就行：

45秒附近有一点卡，把打完后多余的停顿剪掉。壮汉进场稍微加速，运镜跟着动作走，但别把对白也加快。监控补上中文机位名和时间码，删掉乱码。结尾等女主问完，再加短促的反转音乐，其他地方少量点缀就好。

我简单总结在这个作品主要改了什么，大家可能在实际创作中遇到不同的问题，我这里分享我优化迭代的思路。

所以你看，第一版不好，不代表这条片子就做不了了。

先把问题说具体一点，是人物没表情，还是动作软绵绵？是镜头不跟人，还是观众没看懂为什么突然开打？有些要重新生成，有些剪掉就好了。

我觉得，做短剧也好、做电影也好，先得让画面有基本的美感，故事说得通，镜头和声音能带着观众看下去。再往后，才是更好的创意、更高的审美，以及你自己的表达。

这篇文章，其实也是这样做出来的。

我用语音输入法，把测试感受和关键步骤说给AI听，再让它整理成文章。中间的聊天截图、角色板、提示词、对比视频和返修过程，也一起留下来放到对应位置。

不然一篇文章全是文字，大家看着累，也很难知道我究竟怎么做的。把素材和过程摆出来，才看得懂，也方便跟着试。

之前大家说vibe coding，现在叫vibe cutting也好，vibe videoing也好，我觉得意思都差不多，我们可以动动嘴，把脑子里的想法变成视频，继续对话把它剪好，甚至再整理成一篇完整的复盘。

写在最后

整体对比下来，我觉得可灵4.0还是有自己的优势。

3D场景和写实质感这两块，我个人是比较认可的。当然，动作衔接和人物表演也还有需要打磨的地方，具体做什么片子，还是得看案例来选。

另一个让我觉得挺好的变化，是有了CLI和MCP以后，我们用Agent做视频方便了很多。

这次直接用可灵账号里的积分，就能让Codex去生成、下载，再接着剪辑；对于已经开放API的模型，也可以按接口接进自己的流程。选择越来越多，不用每一步都自己切软件操作。

作为用户，我当然很开心看到更多视频模型出来。我也不希望最后变成字节跳动一家独大，大家只能用同一个平台。

我们有更多选择，平台之间有竞争，技术才更有动力往前走，价格也不至于太离谱。

谁在什么场景下做得好、用起来顺手、价格合适，我们就选谁。

我觉得这样挺好的。

闲鱼捡漏自动化：ai-goofish-monitor 部署与使用全记录

闲鱼捡漏这件事，难点从来不是”买”，而是”看见”。

好东西挂出来的窗口期可能只有几十分钟，你不可能 24 小时盯着搜索页刷新。所以我一直在找能替我盯着的工具，最近把 GitHub 上的 ai-goofish-monitor 完整装了一遍——Playwright 抓页面、多模态模型看图判断、命中就推手机。这篇是部署过程 + 使用说明，包含我踩的两个坑。

一、它到底做了什么

一句话：你写一句人话需求，它定时去闲鱼搜，把商品图发给视觉模型判断值不值得买，值得就推送给你。

拆开看是四层：

层 干的事
采集 Playwright 驱动 Chromium 打开闲鱼搜索页，翻页、抓详情、抓卖家信息、下图
判断 把图片 + 文案丢给多模态模型，对照你的”标准”输出推荐/不推荐
提醒 ntfy、企业微信、Bark、Telegram、PushPlus、Webhook 任选
管理 Web 界面：任务、账号、AI 标准、日志、结果、设置

任务、结果、价格历史都存在一个 SQLite 文件里（data/app.sqlite3），登录态、日志、图片还是文件形式。比起早期版本扫一堆 jsonl，这版查询和导出让日常使用顺手很多。

二、两条部署路线，先选一条

路线 适合 代价
Docker（官方推荐） 想长期挂着跑、不想碰 Python 环境 要装 Docker，镜像得走国内加速
Windows 本地 Python 想改代码、想看得见浏览器在干嘛 要装 Python + Node，前端要自己构建

我选的是本地部署，因为想确认它到底抓到了什么。下面按这条路线写，Docker 放最后。

环境要求不高：Python 3.10+、Node 18+、一个支持图片输入的模型 API Key。

三、本地部署实录

1. 拉代码

仓库不大，深度克隆只有 7 MB 左右。国内直连卡住的话加个代理：git -c http.proxy=http://127.0.0.1:7897 clone ...。

2. Python 依赖

用 requirements-runtime.txt，不是 requirements.txt——后者多带了 pytest 和 coverage，跑服务用不上。

坑一：injected 镜像源 403。 我一开始习惯性挂了清华源，pip 直接报 403 Client Error 然后 Could not find a version that satisfies the requirement python-dotenv (from versions: none)。这个报错极具误导性，看着像包名写错，实际是源被拦。去掉 -i 用官方源就正常了：

3. 浏览器内核

它靠 Playwright 自带的 Chromium 跑无头模式，跟系统里装的 Chrome 是两回事，这一步别省。

4. 前端构建

157 个包，一分钟左右。坑二在这里：构建产物不是落在 web-ui/dist，Vite 配置里 outDir 指向了 ../dist，也就是仓库根目录的 dist/。你如果在 web-ui 里找 dist 找不到，别以为构建失败了——后端只认根目录那个。

构建完确认 ai-goofish-monitor\dist\index.html 存在，否则打开页面会收到一句”前端构建产物不存在，请先运行 cd web-ui && npm run build”。

5. 配置文件

四、.env 只需要认真填三行

模型必须能看图，否则”判断成色”这件事根本无从谈起。PROXY_URL 可以只给 AI 请求单独挂代理，不影响爬虫。

Web 界面账号在同一文件：

注意 README 里说默认密码是 admin123，而 .env.example 里写的是 admin123。以 .env 为准，这是官方文档没对齐的地方。

几个容易忽略的开关：

  • RUN_HEADLESS=true：无头跑。想盯着浏览器看它在点什么，临时改 false
  • PCURL_TO_MOBILE=true：商品链接转移动端，抓取成功率更高
  • AI_DEBUG_MODE=true：调 Prompt 时打开，能看到模型收到了什么、回了什么
  • TASK_FAILURE_THRESHOLD=3：连续失败 3 次自动暂停任务 24 小时——这是防 cookie 失效后被反复风控的保险丝，别关

通知配一个就够，我用的 ntfy：手机装个 App，订阅一个自建 topic，.env 里填 NTFY_TOPIC_URL，命中就弹。

五、启动与第一次使用

  • Web UI：http://127.0.0.1:8000
  • API 文档：http://127.0.0.1:8000/docs

首次启动会自动建库建表。

导入闲鱼登录态（关键一步）

没有登录态，爬虫抓到的永远是空列表。仓库自带一个 Chrome 扩展，比手工抠 cookie 靠谱：

  1. chrome://extensions → 开”开发者模式” → “加载已解压的扩展程序” → 选仓库里的 chrome-extension 目录
  2. 打开 goofish.com 并登录
  3. 点扩展图标 → Extract Login State → Copy to Clipboard
  4. 回到 Web UI 的「闲鱼账号管理」粘贴保存

它导出的不只是 cookie（含 HttpOnly），还有 UA、时区、屏幕尺寸这些环境指纹，模仿真实会话用。

登录态通常几天到几周失效一次，失效的表现是结果一直是空、日志里刷 cookie 报错，重新导一遍覆盖就行。

关键词判断 价格合适就想看 填关键词规则，直接建任务，不调模型，不花钱

三条硬性限制，装之前务必对照：

  • Windows 上只有 NVIDIA 能吃到 GPU 加速。 AMD 显卡（包括 Ryzen AI 核显）在 Windows 下只能跑 CPU，因为 PyTorch 没发 Windows 版 ROCm 轮子。想用 AMD 加速得去 Linux。
  • Intel Mac 不支持本地后端。 UI 能装，Python 后端跑不起来（PyTorch 不再发 Intel Mac 轮子）。只能连远程后端用。
  • 首次启动会下载模型权重，几个 GB，启动画面有进度条。这一步慢是正常的，之后就秒开。

实测数据在项目 docs/benchmarks.md，各种引擎的耗时和显存占用都有——建议装之前先看你自己显卡对应哪一档。

官方 docs/performance.md 里点名了一个经典问题：

声音档案的 Transcript（转录文本）字段为空，会让每次生成都多跑一遍完整 Whisper 转录。

旧版本（v0.3.15 之前）是每次生成都跑，表现为”更新后 TTS 突然变得巨慢、CPU 100%”。新版本会自动转录一次并写回档案，但如果你是导入的或手改过的声音档案，那个框可能还是空的，就继续每生成一次付一次 ASR 的代价。

九、适合谁 / 不适合谁

适合：

  • 做自媒体，需要多语种配音又不想按分钟付费的
  • 想做有声书、播客，需要长文本 + 分章 + .m4b 的
  • 对数据敏感，音频不能上传云端的
  • 想让 AI agent 用自己的声音说话，折腾 MCP 的

不适合：

  • 追求开箱即用零折腾——它是 active beta，版本之间确实会出毛病
  • 只有 Intel Mac 或 AMD 显卡 + Windows 还要 GPU 加速的
  • 想要英语广播级音质、不想调参数的——暂时还是 ElevenLabs 更稳
  • 打算嵌入闭源产品商业分发——AGPL-3.0 会传染，得单独买商业许可

小结

VoiceStudio 这类项目的价值不在于”比商业产品更好”，而在于把一条原本按字符收费的流水线，变成了可以自己拥有、自己改的东西。

  • 想最干净：Docker 一条命令 docker compose -f docker-compose.release.yml up，环境完全隔离（国内记得配镜像源）。

四、第一次打开，只要填三项

首次启动时，程序会从 config.example.toml 自动生成一份 config.toml。绝大多数设置都能在 WebUI 的「基础设置」面板里填，会自动保存，不用手改文件。

要填的其实就三项：

  1. LLM 供应商 + API Key —— 选一个（默认是 Kimi/Moonshot），把 Key 填上。这一步不填，后面什么都生成不了。
  2. 语音 —— 保持默认的 Edge TTS 就好，免费。
  3. 素材来源 —— 填 Pexels 的 API Key（去 pexels.com/api 免费注册），或者把 video_source 改成 local，用自己放进去的素材。

顺手值得调的还有两个：

  • edge_tts_timeout：Edge TTS 单次请求超时。网络慢的话调大一点。
  • subtitle_provider：字幕默认 edge（免费、快）；想更准可以切 whisper，但首次要下载模型，CPU 上会慢。

五、生成一条视频是什么体验

回到主页，在主题框里输入你想做的内容，比如：

AI 如何改变普通人的日常生活

点生成，接下来它会自己走完这一串：

  1. 调大模型写一段视频文案
  2. 把文案拆成关键搜索词，去素材库拉对应的视频片段
  3. 用 Edge TTS 合成配音
  4. 生成字幕、配上背景音乐
  5. 渲染合成，输出成片

几分钟后你会在任务目录里拿到结果（config.toml 里可以设成生成完自动打开目录）。成片不满意，可以在界面上试听语音、换字体、换背景音乐，再重新导出。

六、到底花多少钱

环节 成本

**所以它不是一个”收费软件”，而是一个”自备 API 的自建工具”**。唯一的持续成本就是调用大模型的那点钱。

七、踩坑与建议

  • 项目路径不要带中文和空格。这类 Python + 多媒体工具链对路径编码很敏感，直接放个 D:\MoneyPrinterTurbo 最稳。
  • 别在 C 盘临时目录里跑。渲染中间产物会占不少空间。
  • 首次跑建议用「本地素材」试。先排除素材源的问题，确认整条链路通了，再去接 Pexels。
  • 网络问题要有心理准备。素材下载、依赖安装、模型调用都可能受网络影响，把代理配好能省很多事（config.toml 里有 [proxy] 段可以直接填）。
  • 音频编码相关的坑：Python 3.13 环境下项目会额外装 audioop-lts，如果看到 audioop 相关报错，检查这个包有没有装上。
  • 别指望零修改出爆款。它的定位是”把你从剪辑里解放出来”，选题、脚本打磨、成片审核，还是得你来。

小结

MoneyPrinterTurbo 是目前这类工具里完成度相当高的一个：WebUI 够用、配置项清晰、语音和素材都有免费方案，一条命令就能跑起来。

我的建议是先用一键包或 Docker 花十分钟跑通一遍，确认工作流符合你的预期，再决定要不要本地部署长期用。先跑通，再优化——这类工具最容易死在”装环境”这一步，而不是”用起来”。

装好之后你会发现，真正花时间的不是生成，而是想清楚要做什么内容。工具把执行的成本压到很低了，剩下的就看你自己的选题了。

昨天注定是载入史册的魔幻一天，DeepSeek 同时放了两个大招！先是 DeepSeek V4 Pro 正式版上线，紧接着万众瞩目的 DeepSeek Harness 开源。炸裂！炸裂！炸裂！

DeepSeek Harness 开源的 GitHub 仓库上线不到 1 天，就冲到了 8 万多 Star，AI 圈的顶流果然名不虚传。这下搞不好 Codex、Claude Code、Cursor 都要”凉了”……

这篇文章我会从安装开始，手把手带你体验 DeepSeek Harness 的核心玩法。小白可懂，建议收藏 ⭐️

建议观看视频版：B站视频

一、DeepSeek Harness 是什么？

Harness 这个词翻译过来就是「驾驭」。如果把 AI 模型比作一匹马，那 Harness 就是你驾驭 AI 模型这匹马所需要的一切工程。

所谓 Harness 工程，就是研究怎么让 AI 模型这匹马跑得更快、更稳，顺利完成任务。你给 AI 写的项目规则文件、配置的各种工具、安排的任务拆分和执行顺序、设计的测试检查流程，这些统统都算 Harness。

有一个很精妙的公式：

Agent = Model + Harness

模型负责思考和生成，Harness 负责把这些能力接入文件系统、终端、网页、工具链，让 AI 真正能在现实环境里干活。

之前 DeepSeek 只开源了模型这一半，Harness 一直没动静，这次终于补齐了。你可以把 DeepSeek Harness 理解成一个可以高度定制的 AI 编程工具，对标 Claude Code 和 Codex。但它的野心比这些工具更大——不只是一个编程 Agent，而是一套可配置、可重组的 Agent 运行环境。官方口号是「一切皆插件」。

三、Harness 实战

界面打开之后，别急着让它干活。第一次用，建议先把下面三件事搞清楚。

1. 选一个”工作现场”

第一步是选择一个项目文件夹。Harness 会把这个目录当成它的工作现场——之后读文件、改代码、跑命令，全部围绕这个目录展开。

这一点很关键：目录选错，它能帮你的范围也就错了。所以第一次实测，我建议不要直接对着你最重要的项目开刀，先建一个空目录玩两把，熟悉了再上真项目。

2. 调三个开关

进入对话后，界面上有几个需要你决定的东西：

  • 模型与推理等级：可以选 DeepSeek V4 Pro 等模型，并调节推理等级。等级越高，它越舍得”想”，但响应更慢、消耗也更大。日常改代码用中等档就够，遇到复杂重构再拉满。
  • 权限范围：Harness 默认会在每一次写文件、执行终端命令前向你确认。刚开始强烈建议保持确认模式，等你摸清它的脾气再考虑放开。
  • 工作模式：最实用的是「标准模式」。它已经预置了一整套 AI 编程工具该有的基础能力（读写文件、执行命令、检索资料、把长任务拆成待办清单等），开箱就能干活。想更轻量或更激进，再去看其他模式。

3. “一切皆插件”到底指什么

官方那句”一切皆插件”不是宣传口号。模型接入、工具能力、执行环境、上下文管理、甚至对外接口，都是可以被替换、被组合的插件。

对普通用户来说，实际意义是：你不需要用它的全部，按需开关就行。用得越少，行为越可控，出问题的面也越小。

4. 实测案例：让它做一个 Excel 周报生成器

光看界面没感觉，我直接上了一个真实需求：把每周的几份数据汇总成一份 Excel 周报。

我给它的原话大概是这样：

在当前目录建一个脚本，读取 data/ 里本周的表格文件，汇总成一份 Excel 周报，包含本周汇总、和上周的环比，输出到 output/ 目录。

接下来发生的事，是这次实测里最有意思的部分：

  1. 它没有立刻开写，而是先把任务拆成了一份待办清单（todo），然后一条条执行、一条条勾掉——你能实时看到它”走到哪一步了”。
  2. 它自己去翻了目录里的真实文件，发现列名和我描述的不完全一样，于是回来问我确认字段含义，而不是硬按自己的假设写下去。
  3. 建目录、写脚本、装依赖、跑一遍验证输出，整个过程里每一次写文件和执行命令都弹了确认，我点了几次”同意”。
  4. 第一版跑出来的表头不对，我只说了一句”周次那一列要按 ISO 周算”，它就定位到对应函数改掉了，并且重跑验证。

整个过程不到二十分钟，我拿到了一份能直接用的周报脚本。

这次实测给我最大的感受是：它和”聊天窗口里让 AI 写代码”完全不是一回事。区别不在于模型多聪明，而在于它能看到真实文件、能执行、能验证、能被打断和纠偏——这才是 Harness 的价值。

5. 给它写好”项目规则”

这是我用完最想安利的一条经验。

在项目根目录放一个规则文件（比如 AGENTS.md），把项目约定写清楚：

  • 用什么语言、什么框架，依赖怎么装
  • 目录结构长什么样，新文件该放哪
  • 改完代码要跑什么检查、什么测试
  • 哪些目录是禁区，不许动

Harness 每次启动都会读这份规则。规则写得越清楚，它越少自作主张；规则含糊，你就得反复纠正。这一步偷懒，后面全是加班。

6. 几个必须提醒的坑

  • 权限别一上来就给满。它能读写文件、能执行命令，就意味着提示词写得含糊时，它可能做出你并不想看到的操作。
  • 推理等级拉满很烧 token。等级越高越慢越贵，注意账户余额，别在简单任务上开满档。
  • 它还在开发者预览阶段。接口会以破坏兼容的方式快速演进，今天写的插件明天可能需要改，别急着上生产环境。
  • 别指望它替代你判断。它能帮你把活干完，但需求是否合理、结果是否正确，责任还是在你身上。

四、小结：值得现在上手吗

一句话总结：DeepSeek Harness 补上了 DeepSeek 生态里一直缺的那一半。

模型能力大家都已经见识过了，真正拉开差距的是”怎么用好”。Harness 把文件系统、终端、工具链、任务编排这一整套东西开放出来，让”用一个模型”变成”组装一个能干活的 Agent”。

我的建议是：

  • 想尝鲜：npx @deepseek-ai/dsh web 一条命令就能跑起来，成本极低，值得试。
  • 想认真用：先花半小时把项目规则文件写好，收益最大的一步就是这个。
  • 想上生产：再等等。开发者预览阶段，接口变化快，现在铺开容易返工。

工具会一直有新的，但”怎么把事情拆清楚、怎么给 AI 划好边界”这套能力，换哪个工具都用得上。

就这样，去玩吧 🎉
